Short Statement

Is unit-time open-shop makespan scheduling with sequence-dependent batch setup times fixed-parameter tractable in the number of batches?

Open Problem

Background & Context

Setup times are a major source of scheduling complexity: changing from one batch or product family to another may require cleaning, tooling, calibration, or travel. In open-shop scheduling, every job has one operation on each machine and the operation order is not prescribed. The batch setup variant groups jobs into batches and charges sequence-dependent setup time whenever a machine switches batch. Even with unit processing times, the model combines shop-scheduling constraints with a sequencing problem resembling TSP on batch labels. Van Bevern and Pyatkin obtained algorithms for important restricted cases, including settings where every batch is larger than the number of machines and settings where both the number of machines and number of batches are constants. Mnich and van Bevern ask for the clean parameterized classification by the number of batches alone. This is a natural OR question because product families may be few while the number of jobs and machines is large.

What Is Known

The model is NP-hard already for one machine because sequence-dependent setup times generalize routing/TSP-style sequencing. Van Bevern and Pyatkin showed that if each batch contains more jobs than the number of machines, the problem is solvable in time roughly exponential only in ggg plus near-linear input handling, and they also obtained polynomial-time solvability when both the number of machines mmm and the number of batches ggg are constants. Mnich and van Bevern state the remaining question as Open Problem 14: FPT in ggg alone. Their discussion emphasizes high-multiplicity encoding, because an algorithm that expands all jobs may be pseudo-polynomial in the batch counts rather than truly efficient for compact instances.

Progress & Literature

Latest progress (Partial progress). Restricted large-batch and constant-(m,g)(m,g)(m,g) cases have algorithms, and high-multiplicity computation is understood for those restricted makespan calculations. The single-parameter dependence on the number of batches remains unresolved. Mnich and van Bevern, 15 open problems van Bevern and Pyatkin, routing open shop with unit processing times

The number of batches is a plausible practical parameter because batch families are often few, but the open-shop constraints allow many interleavings across machines. The known large-batch algorithm suggests that once each batch has enough jobs, machine schedules can be regularized; the unresolved case is where small batches create scarcity and synchronization effects. A positive result would need to show that all relevant setup patterns can be represented by a bounded object depending only on ggg, even while mmm and the job counts vary. A high-multiplicity result would be stronger: it must reason about counts arithmetically rather than by expanding every job. A negative result would likely need a reduction in which the number of batch labels stays small but their transition matrix and counts encode a hard selection problem.
