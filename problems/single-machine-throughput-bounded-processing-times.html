Open Problem

Settle the polynomial-time and parameterized complexity of single-machine throughput scheduling with release dates and constant-bounded processing times.

Background & Context

Maximum-throughput scheduling asks which jobs can be completed by their deadlines. It is a clean single-machine model for admission control: each job has a release date, deadline, and processing time; jobs completed late contribute no throughput. The unit-processing-time case is tractable by matching or greedy methods, while arbitrary processing times make the problem NP-hard. The boundary where processing times are bounded by a fixed constant is surprisingly delicate. Sgall's survey and Mnich-van Bevern's parameterized open-problem list highlight the question 1∣rj,pj≤c∣∑jUj1|r_j,p_j\le c|\sum_j U_j1∣rj​,pj​≤c∣∑j​Uj​: for each fixed constant ccc, is there a polynomial-time algorithm for maximizing the number of on-time jobs? The weighted version and parameterized versions are also open-looking. This is exactly the kind of problem the repository is meant to include: the model is fixed, small, and classical, but the complexity frontier is not known.

What Is Known

When all processing times are unit, maximum throughput on one machine with release dates and deadlines has classical polynomial algorithms. With arbitrary processing times, throughput scheduling is NP-hard and heavily studied in approximation and online scheduling. Sgall's survey on maximum throughput scheduling asked whether 1∣rj,pj≤c∣∑jUj1|r_j,p_j\le c|\sum_j U_j1∣rj​,pj​≤c∣∑j​Uj​ is polynomial-time solvable for constant ccc; Mnich and van Bevern restate this and add parameterized versions. They also note that the NP-hardness of the weighted case for constant ccc is open. The issue is that bounded processing times make time-indexed dynamic programs plausible, but release-date/deadline interactions still create global interval-packing structure. A later search did not find a source resolving the exact fixed-ccc complexity frontier.

Progress & Literature

Latest progress (open). Polynomial algorithms are known for unit processing times, and hardness is known for broader processing-time regimes. The fixed constant-bounded processing-time frontier remains unresolved in the cited open-problem list. Parameterized complexity of machine scheduling: 15 open problems

The problem is a boundary case in single-machine scheduling. Unit jobs can be handled because the time axis decomposes cleanly, but arbitrary processing times allow knapsack-like hardness. If every processing time is at most a fixed constant ccc, the input has only a bounded set of job lengths, suggesting that a clever dynamic program or flow formulation may exist. On the other hand, release dates and deadlines can encode many interval interactions even with short jobs. Mnich and van Bevern propose parameterized complexity as an intermediate route: even if the polynomial-time question is difficult, classifying FPT behavior with respect to ccc or the number of distinct processing times may expose the right structure.
